# 运维指南

## 数据与密钥备份

先等待当前任务结束，再停止 API 与 worker。备份整个 `FLOW_DATA_DIR` 和仓库中的 `.env`，并限制备份访问权限。

数据目录包含 SQLite、可能存在的 WAL / SHM 文件、加密配置、SSH 凭据、运行记录、日志、构建产物、缓存和工作目录。**`master.key` 必须与数据库一起备份**；丢失后无法解密既有项目配置、任务快照和凭据。不要只复制 SQLite 主文件或只备份源码。

以 systemd 为例：

```sh
sudo systemctl stop flow-lite-worker.service flow-lite-api.service
# 将完整数据目录、.env 与自有部署配置复制到受控备份位置。
sudo systemctl start flow-lite-api.service flow-lite-worker.service
```

使用 PM2 时对应操作为：

```sh
pm2 stop flow-lite-worker flow-lite-api
# 备份完整数据目录与 .env。
pm2 start flow-lite-api flow-lite-worker
```

恢复时使用同一份数据库和 `master.key`，保留运行账号的目录权限。TLS 私钥、Nginx 配置及外部项目的数据由各自既有备份流程管理，不应放进公开仓库或发布包。

## 升级

确认没有运行中的任务，备份后停止两个进程。以运行账号更新代码和依赖，构建前端，再同时启动 API 和 worker：

```sh
git pull --ff-only
npm ci
npm run check
npm test
npm run build
```

不要用示例文件覆盖已有 `.env`、数据目录或密钥。systemd 配置有改动时先验证配置并执行 `daemon-reload`；仅更新业务代码不需要重新申请 TLS 证书。

## 任务恢复与文件状态

执行器使用持久化队列和独占租约，避免多个 worker 同时执行。重启后，原先运行中的任务标记为中断失败，不自动重跑；排队任务继续保留。新 Node.js 构建前，执行器清理属于本平台实例的遗留构建容器。

host 构建或原地命令被强杀后，需检查残留进程。远程命令支持独立进程组时，会在取消时另开 SSH 连接尝试终止；网络中断或目标机不可达时，无法确认远程操作是否已经完成或停止。

取消、重试、升级和服务重启不撤销已经完成的文件修改、数据库操作或外部请求。原地命令重试前先检查目标目录和服务的实际状态。

## 日志与产物留存

- 单次任务日志上限为 10 MB，达到上限后省略后续输出。
- 成功发布或执行命令后清理 30 天以前的已结束任务日志；运行记录继续保留。
- Node.js 默认保留最近 5 个可回滚构建，并保护当前版本及排队回滚需要的版本。
- 较早记录即使仍可查看，也可能已没有可回滚产物。清理任务失败会写入对应运行日志，应同时检查磁盘使用。
- 删除项目配置会删除对应记录和平台本地产物，已有目标目录中的网站文件保持原状。

查看服务日志：

```sh
sudo journalctl -u flow-lite-api.service -u flow-lite-worker.service -n 80 --no-pager
# 或使用 PM2：
pm2 logs flow-lite-api
pm2 logs flow-lite-worker
```

分享日志前确认其中没有脚本主动输出的业务数据。平台按已配置的原始敏感值脱敏，不代表能够识别脚本生成的所有编码、转换或外部系统信息。

## 常见问题

| 现象                      | 检查方向                                                                                                  |
| ------------------------- | --------------------------------------------------------------------------------------------------------- |
| Node.js 任务一直排队      | Docker daemon、运行账号的 Docker 权限、镜像仓库连通性，以及 worker 日志                                   |
| 命令找不到 PHP / Composer | 执行账号的非交互 `PATH`，或使用已安装工具的绝对路径                                                       |
| SSH 认证失败              | 用户名、目标服务允许的认证方式、所选凭据，以及主机与端口对应的 `known_hosts`                              |
| HTTPS 仓库认证失败        | 仓库 URL、HTTPS 凭据类型、账号、密码 / 令牌有效期与仓库读取权限；GitHub 需令牌，另检查执行机的 TLS 信任链 |
| 日志不实时更新            | Nginx 的 SSE 缓存与超时配置，以及 API / worker 是否同时运行                                               |
| HTTPS 登录后无法保持会话  | 同源代理、`FLOW_SECURE_COOKIE`、实际访问协议和浏览器 Cookie                                               |
| 已发布但站点不可访问      | Nginx 是否指向 `<发布根目录>/current`，以及目录穿越、读取权限                                             |
| 历史版本不能回滚          | 产物是否已清理，当前项目类型或发布目标是否已改变                                                          |
| 配置和凭据无法解密        | 数据库与 `master.key` 是否来自同一份备份，密钥文件是否被覆盖                                              |

证书续期属于部署环境的证书管理流程。单独检查其定时任务、域名解析、验证路由及实际到期日期，不把面板健康检查当作续期成功证明。
